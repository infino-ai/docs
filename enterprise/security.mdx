This page describes how Infino Enterprise protects your data. The verified controls are
below; items still being finalized are marked as team TODOs.

## Authentication

Every request is authenticated with an **API key** presented as an
`Authorization: Bearer <key>` header. Keys begin `ik_…` and are created and scoped from
your dashboard. A request without a valid key for the target database is rejected. See
[Authentication](/enterprise/authentication) for how the key is supplied and sent.

## Encryption in transit

`https://` is required for the hosted endpoint, so all traffic, including the bearer
token, is encrypted with TLS. A remote `http://` URL is rejected at `connect`, so a key
never travels over an unencrypted connection. Plain `http://` is accepted only for
loopback (`localhost` / `127.0.0.1`) during local development.

## Encryption at rest

Your data is stored as Parquet on object storage and is encrypted at rest by the object
store.

## Tenant isolation

Each database is isolated per tenant. An API key grants access only to the databases it
is scoped to, and a query is routed and executed against only that tenant's data.

## Key rotation

Rotate a key from your dashboard: create a new key, roll it out to your deployments, then
revoke the old one. Revocation takes effect immediately. See
[Authentication](/enterprise/authentication#rotating-a-key).
