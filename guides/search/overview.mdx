Infino retrieves from the same table several ways. Pick the mode that matches the
question; you can also compose any of them in [SQL](/sql-reference).

## Choose a search mode

| You want to… | Use | Why |
| --- | --- | --- |
| Match exact keywords or terms | [Full-text (BM25)](/guides/search/full-text) | Lexical ranking over tokenized text |
| Find by meaning / paraphrase | [Vector kNN](/guides/search/vector) | Semantic similarity over embeddings |
| Cover both keyword and semantic intent | [Hybrid](/guides/search/hybrid) | RRF fuses BM25 + vector rankings |
| Look up an exact id or value | `exact_match` ([full-text](/guides/search/full-text)) | Unranked, precise |
| Filter, aggregate, or join | [SQL](/sql-reference) | Compose over the same rows |

## What each mode supports

| Mode | Ranked | Tunable recall | Text pre-filter | Compose in SQL |
| --- | --- | --- | --- | --- |
| BM25 | ✓ | — | — | ✓ (`bm25_search`) |
| Vector kNN | ✓ | ✓ (`nprobe`) | ✓ (pushdown) | ✓ (`vector_search`) |
| Hybrid | ✓ (RRF) | ✓ | — | ✓ (`hybrid_search`) |
| `token_match` / `exact_match` | — | — | — | ✓ |
| SQL | — | — | — | native |

<Tip>
Always pass a sensible top-`k` on production queries — it bounds both the work and the
result size. Every search returns Arrow rows; pass a `projection` to choose which
columns come back.
</Tip>
