Requests to [Infino Cloud](/cloud/quickstart) are authenticated with an **API key**. This
page covers where the key comes from, what it may do, how to supply it, how it travels on
the wire, and how to rotate or revoke it.

## API keys

An API key is a string beginning `inf_…`, created in the Infino Cloud console at
[platform.infino.ws](https://platform.infino.ws) — the only place keys are minted (there
is no SDK or API call to create one). Treat it like a password.

### What a key may do

When you create a key you choose two things. Both are fixed for the life of the key.

**Capabilities**, any combination of:

| Capability | Grants |
| --- | --- |
| `read` | searches, `count`, reading a schema, listing tables |
| `write` | `append`, `update`, `delete` |
| `manage` | creating and dropping tables, changing a table's schema, creating and deleting databases |

A new key has all three unless you clear some. A read-only key is the right one to give a
query service or an agent that should never change data.

**Database scope**: all databases in the account, a chosen set of them, or a pattern that
database names must match.

A call the key is not allowed to make returns HTTP `403`, whether it is missing the
capability or addressing a database outside its scope. A key the service does not know
returns `401`.

Creating, rotating and revoking keys needs the Member role or higher in your
organization. Viewers cannot see or create keys.

### Supplying the key

You give the key to `connect` in one of two ways.

**Pass it explicitly:**

<CodeGroup>

```python Python icon="python"
import infino

db = infino.connect("https://api.platform.infino.ws/my-app", api_key="inf_…")
```

```typescript Node.js icon="node-js"
import { connect } from "@infino-ai/infino";

const db = connect("https://api.platform.infino.ws/my-app", { apiKey: "inf_…" });
```

```rust Rust icon="rust"
use infino::{connect_with, ConnectOptions};

let db = connect_with(
    "https://api.platform.infino.ws/my-app",
    ConnectOptions::new().with_api_key("inf_…"),
)?;
```

</CodeGroup>

**Or read it from the environment.** Set `INFINO_API_KEY` and the key argument becomes
optional. This keeps the secret out of your source:

```bash
export INFINO_API_KEY="inf_…"
```

<CodeGroup>

```python Python icon="python"
db = infino.connect("https://api.platform.infino.ws/my-app")
```

```typescript Node.js icon="node-js"
const db = connect("https://api.platform.infino.ws/my-app");
```

```rust Rust icon="rust"
let db = connect("https://api.platform.infino.ws/my-app")?;
```

</CodeGroup>

<Tip>
Prefer `INFINO_API_KEY` over hard-coding the key. It keeps the secret out of your code
and version control, and lets deployment tooling inject it at runtime.
</Tip>

## How the key is sent

The API key is sent as an HTTP `Authorization: Bearer <key>` header on every request:

```http
Authorization: Bearer inf_…
```

**`https://` is required for any remote host** so the key is never sent in the clear.
Plain `http://` is accepted only for `localhost` / `127.0.0.1` (loopback), for local
development against a service you run yourself. A remote `http://` URL is rejected at
`connect`, so a bearer token never travels over an unencrypted connection.

## Rotating a key

Rotate a key from the API Keys page of the [console](https://platform.infino.ws). **Rotate**
issues a new secret with the same capabilities and database scope. The old secret keeps
working for 24 hours and then expires, so you can roll the new one out to your
deployments (update `INFINO_API_KEY` or the value you pass to `connect`) with no downtime.

## Revoking a key

If a key has leaked, do not wait out the rotation overlap: **Revoke** it. Revocation takes
effect within about 30 seconds. Create the replacement first if something still depends
on the key.
